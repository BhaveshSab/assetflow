# The learning log

> One entry per day. Thirty lines, no more. It is the fastest way to turn
> "I read about it" into "I did it, here is the output, here is what
> surprised me".
>
> The interview questions come from *these* entries.

| Date | What I did | What surprised me | What I would do differently |
|------|-----------|-------------------|-----------------------------|
| YYYY-MM-DD | | | |

## The template

```markdown
## YYYY-MM-DD — the topic

**What I did**
- the command, the output

**What surprised me**
- the thing I did not expect

**The question it raises**
- the thing I still do not understand
```

## The first ten topics (in this order)

1. `lsblk`, `df -h`, `du -xh --max-depth=1 /` — find the space
2. `ps`, `top`, `htop`, `kill` — find the process
3. `systemctl status`, `journalctl -u x -f` — the service
4. `ssh`, `~/.ssh/config`, key authentication — the remote host
5. `dig`, `nslookup`, `curl -v`, `ss -ltnp` — the network
6. `grep`, `sed`, `awk`, `sort`, `uniq` — the text
7. `chmod`, `chown`, `umask` — the permissions
8. `tar`, `gzip`, `sha256sum` — the archive
9. `crontab -e`, `systemctl list-timers` — the schedule
10. `docker ps`, `docker logs`, `docker exec` — the container
